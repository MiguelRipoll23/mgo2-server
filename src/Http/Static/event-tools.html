Event testing tools

Drive one lobby's entry pipeline. Every team is a row, whether a player formed it or you created it here from the test-character pool, and the entry pipeline queues and pairs it the same way. Fill a team with test players and use the menus — there is nothing to type but a name.

The running lobby of this mode answers; a mode with no lobby says so rather than failing later.

Create a team

A team of test players drawn from the test-character pool. It is a row like any other, so it is queued for pairing and can be matched against a team a player formed.

The leader is one of them.

Add players to a team

Fills any team of this lobby, whether a player formed it or this page created it. The slots are filled already ready, because there is nobody to press the button that joins a team.

Every team this lobby holds.

Move a team to a state

Sets the stored state byte and optionally forces the member byte on the roster. A team a player formed has its state owned by the entry pipeline, so a value set on one is overwritten by its next decision.

Ready a stored team's fake players

Fake players added to a stored team are written in whatever state that team's own state implies — for an open team, the one the client paints NG — and nobody else can change it: a fake player has no button, and a real player only decides for themselves. This moves the fake ones. A real member's decision and the team's own state are left alone.

A pairing needs somewhere to go

A pairing is written when two teams are queued, but it is not announced until a room has been leased for it — and a room is only leased from one that is named for the role, says it is dedicated and is sitting idle with its host present. All of that is something a real host client does just by existing, so a pairing made from this page waits for a room nobody has opened. This creates one, which is the difference between paired — waiting for a host room and a match the client is actually told about.

The room's host is a real character: the column is a foreign key and the host has to be present in the room. Leave it at 0 to take the first character there is.

Teams in this lobby

Every row of the lobby, in any state: the teams a player formed and the ones these tools created. These are the teams the entry pipeline queues and pairs, so a team waiting here is waiting to be matched.

Pairings this lobby is holding

What the entry pipeline has paired, and what each match is waiting for. A pairing is only announced to its teams once a room has been leased for it, so a pair that has matched and a pair still waiting for a host look identical from in game — this list is where the two are told apart. Made here marks the side whose players were created by these tools; a match needs a room named SURVIVAL_HOST in the Survival Hosts lobby, idle and dedicated, before it is announced.
