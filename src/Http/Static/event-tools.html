Event testing tools

Drive one lobby's entry pipeline. Teams a real player formed are read from the database; teams you create here exist only in a lobby's memory and are gone when it restarts. Fill either kind with players who are not really there, and use the menus — there is nothing to type but a name.

The running lobby of this mode answers; a mode with no lobby says so rather than failing later.

Create a team

A team that lives in the lobby's memory only. It is never queued and never paired on its own, because the queue is built from the database — use Queue for pairing below to give it a row when you want it matched.

The leader is one of them.

Add players to a team

Fills any team of this lobby, whether a player formed it or this page created it. The slots are filled already ready, because there is nobody to press the button that joins a team.

Both kinds of team this lobby holds, grouped by which they are.

Move an in-memory team to a state

In-memory teams only, because a real team's state is owned by the entry pipeline: setting one from here would be overwritten by the next decision, and nothing here writes a row.

Teams a player formed

Rows in the database, in any state. These are the teams the entry pipeline queues and pairs, so moving one of them to a waiting state here would do nothing.

Teams in this lobby's memory

What the lobby holds in memory right now, with no row behind any of it. A restart empties this list. Queue for pairing is the one action here that writes: it turns the team into a stored one and puts it in the queue, which is what lets a real team be matched against it. The row it writes stays afterwards so the pairing can be inspected. Survival only — a Tournament entrant is seeded into a bracket and frozen, which a memory-only team cannot be.
